# Security Policy

## Scope

Aletheia is an experimental research project.

Security considerations are especially relevant to components involving:

- external tools
- persistent memory
- research data
- experiment execution
- automated reasoning
- future autonomous actions

## Reporting a Vulnerability

If you discover a security vulnerability in Aletheia, please do not disclose it publicly through a GitHub Issue.

Instead, report it privately through GitHub's available security reporting mechanisms.

Please include:

- a description of the vulnerability;
- the affected component;
- steps required to reproduce the issue;
- potential impact;
- and, when possible, a proposed mitigation.

## Research and Experimental Limitations

Aletheia is experimental software.

Experimental components may contain:

- implementation vulnerabilities;
- unexpected behavior;
- incomplete validation;
- unsafe assumptions;
- or limitations that have not yet been identified.

The project should therefore not be deployed in security-critical or safety-critical environments without independent evaluation.

## Security Philosophy

Security should be treated as part of the research process.

As Aletheia becomes more autonomous, future development will prioritize:

- bounded permissions;
- explicit resource limits;
- auditable actions;
- reproducible behavior;
- verification before execution;
- and human oversight where appropriate.
